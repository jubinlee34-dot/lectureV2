# next-action

## 목적
현재 상태를 근거로 다음 작업 후보를 최대 3개 제안한다.

## 사실 기준
- 계획·우선순위·결정: Notion
- 실제 구현 상태: GitHub
- 충돌 시 GitHub를 우선하고 차이를 보고한다.

## 실행 조건
- 사용자가 `다음 작업`, `우선순위`, `이어서 작업` 등을 요청했을 때 사용한다.
- 사용자가 이미 구체적인 작업을 지시했다면 사용하지 않는다.

## Context Budget
1. Notion은 최신 작업 리스트와 현재 후보와 직접 관련된 기록만 우선 읽는다.
2. GitHub는 branch / HEAD / origin/main / working tree, 관련 PR·CI, 최근 main부터 확인한다.
3. 관련 파일 탐색은 좁게 시작하고, 증거가 부족할 때만 확대한다.
4. 과거 대화 전체나 저장소 전체를 기본 입력으로 사용하지 않는다.

## 판단 순서
1. 개인정보 / 보안 / 데이터 손실 위험
2. 기능 오류
3. 상업화 필수 기능
4. 외부 서비스 연동
5. 사용성 / UX
6. 디자인

## 출력
최대 3개만 제안한다.

1. 작업명 — 지금 해야 하는 이유 / 근거
2. 작업명 — 이유 / 근거
3. 작업명 — 이유 / 근거

사용자가 번호를 선택하거나 승인할 때까지 실행하지 않는다.

## 금지
- 기억만으로 작업을 추정하지 않는다.
- 존재하지 않는 문제나 파일을 만들어내지 않는다.
- 후보 제시 후 자동 구현하지 않는다.
- commit, push, PR, merge를 자동 실행하지 않는다.
