# next-action

## 목적
현재 lectureV2 상태를 근거로 다음 작업 후보를 최대 3개 제안한다.

## 사실 기준
- 작업 계획·우선순위·결정 기록: Notion
- 실제 구현 상태: GitHub
- 둘이 충돌하면 GitHub 실제 상태를 우선하고 차이를 보고한다.

## 입력 소스
가능한 범위에서 아래를 확인한다.
1. Notion의 lectureV2 최신 작업 리스트
2. 현재 branch / HEAD / origin/main / working tree
3. 열린 PR과 CI 상태
4. 최근 main 변경
5. 현재 미완료·보류 작업

## 판단 순서
1. 개인정보 / 보안 / 데이터 손실 위험
2. 기능 오류
3. 상업화에 필수적인 기능
4. 외부 서비스 연동
5. 사용성 / UX
6. 디자인 / 시각 개선

## 출력
다음 형식으로 최대 3개만 제안한다.

1. 작업명 — 왜 지금 해야 하는지 / 근거 소스
2. 작업명 — 왜 지금 해야 하는지 / 근거 소스
3. 작업명 — 왜 지금 해야 하는지 / 근거 소스

마지막에 사용자가 번호를 선택하거나 승인할 때까지 멈춘다.

## 금지
- 과거 대화 기억만으로 다음 작업을 추정하지 않는다.
- 존재하지 않는 문제나 파일을 만들어내지 않는다.
- 후보를 제시한 뒤 자동으로 구현하지 않는다.
- commit, push, PR, merge를 자동 실행하지 않는다.
