# scope-lock

## 목적
구현 전에 이번 작업의 경계를 짧고 명확하게 고정한다.

## 작성 항목
### GOAL
이번 작업의 단일 목적을 1문장으로 작성한다.

### SCOPE IN
이번 작업에서 수정·확인해야 하는 기능과 파일 범위를 작성한다.

### SCOPE OUT
이번 작업에서 건드리지 않을 영역을 반드시 작성한다.
- 관련 없는 리팩터링
- 요청하지 않은 신규 기능
- 승인되지 않은 DB / 인증 / 환경변수 / 보안 / 배포 변경
- 디자인 전면 개편 등 자연스럽게 확장될 수 있는 작업

### DONE EVIDENCE
완료를 확인할 수 있는 검증 항목을 작성한다.
예:
- `pnpm run check` 통과
- `pnpm run build` 통과
- `git diff --check` 통과
- 지정 브라우저 E2E 시나리오 확인

### RISK
DB, migration, 인증, 개인정보, 외부 API, 데이터 손실 가능성을 표시한다.

## 규칙
- 한 작업에는 하나의 목적만 둔다.
- 구현 중 다른 문제를 발견해도 현재 SCOPE OUT이면 수정하지 않고 후속 작업 후보로 기록한다.
- IN에 포함된 파일이라도 요청하지 않은 기능 변경은 허용되지 않는다.
- 위험 작업은 AGENTS.md의 승인 경계를 따른다.
- 간단한 1파일 버그 수정은 필요 시 축약형으로 작성할 수 있다.

## 출력 예시
GOAL: 삭제된 강의의 할 일이 할 일 페이지에 남지 않도록 수정
IN: 관련 조회/필터 로직, 관련 테스트
OUT: 휴지통 UI 재설계, DB 스키마 변경, 검색 기능 변경
DONE: check/build/diff 통과 + 삭제 후 할 일 미노출 확인
RISK: 데이터 삭제 로직 회귀 가능성
