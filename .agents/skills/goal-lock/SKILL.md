# goal-lock

## 목적
scope-lock 또는 사용자 승인 계획을 실행 계약으로 사용해 목표 이탈을 막고, 실제 검증 증거가 있을 때만 완료로 보고한다.

## 입력 계약
- scope-lock 결과가 있으면 그대로 사용하고 재작성하지 않는다.
- 없으면 사용자가 승인한 GOAL / IN / OUT / DONE / RISK만 최소 추출한다.
- 승인 경계는 AGENTS.md를 따른다.

## 실행 루프
### PLAN
- 수정 대상과 접근 방법만 짧게 정리한다.
- 승인 밖 변경이 필요하면 구현 전에 멈춘다.

### DO
- IN 범위만 수정한다.
- 범위 밖 발견사항은 후속 후보로 남긴다.

### VERIFY
- DONE에 정의된 검증을 실제 실행한다.
- 마지막 수정 이후 검증을 다시 실행한다.
- 필요한 경우 기본 검증(`pnpm run check`, `pnpm run build`, `git diff --check`)과 E2E/DB/콘솔 검증을 보완한다.

### REPORT
- 실패·미검증 항목을 먼저 보고하고 성공 증거를 뒤에 보고한다.

## 완료 금지 조건
다음 중 하나라도 해당하면 `완료`로 보고하지 않는다.
- DONE 실패 또는 미실행
- 마지막 수정 후 재검증 없음
- 필요한 사용자 기능/E2E 증거 없음
- OUT 또는 승인 경계 침범
- 실행 없이 추론만으로 성공 판단

## 금지 패턴
- 실패 테스트 삭제·skip
- 기준 완화
- 테스트 맞춤 하드코딩
- 오류 로그 숨김
- 낮은 증거 수준을 전체 기능 검증으로 과장
- 미검증 상태를 성공처럼 표현
